# ZKThunder ↔ Mintlayer Public-Input Encoding Contract

> **STATUS: DRAFT — EXTERNAL AUDIT PENDING.** Every item marked **[VERIFY]** must be confirmed
> against the zkthunder source (`core/lib/prover_interface/src/outputs.rs`,
> `core/lib/zkevm_circuits`, and the L1 verifier contract) before PR 2 lands. This document is
> the single source of truth for how the four SNARK public inputs relate to the fields recorded
> in a `ZkBatchSettlement` output. A mismatch anywhere in this document is a
> **false-settlement vulnerability** (a proof attesting to X verifies against a settlement of Y).

## 1. What the proof attests

The SNARK wrapper circuit's public inputs are the four `aggregation_result_coords`:

```rust
pub aggregation_result_coords: [[u8; 32]; 4],
```

Semantic order **[VERIFY — index order]**:

| idx | meaning |
|-----|---------|
| 0 | L2 state root **after** the batch |
| 1 | L2 state root **before** the batch |
| 2 | hash of all L2→L1 logs in the batch |
| 3 | bootloader initial heap contents hash |

These are serialized BN254 scalar-field elements. **[VERIFY]** serialization form: 32-byte
big-endian, most significant byte first, non-canonical (non-minimal) encodings rejected by the
wrapper circuit — confirm.

## 2. What the settlement output records

`ZkBatchSettlementData` (defined in `common/src/chain/zk.rs`) carries:

```rust
pub l2_chain_id: u64,
pub batch_number: u64,
pub prev_state_root: [u8; 32],   // coord 1 — see §5
pub state_root: [u8; 32],        // coord 0
pub l2_to_l1_log_hash: [u8; 32], // coord 2
pub heap_hash: [u8; 32],         // coord 3
pub protocol_version: u32,
pub proof_type: u8,              // advisory only; CBOR tag is authoritative (plan D4)
pub proof: Vec<u8>,
```

## 3. Reconstruction rule (normative)

The verifier MUST build the public-input array as:

```text
public_inputs[0] = data.state_root
public_inputs[1] = data.prev_state_root
public_inputs[2] = data.l2_to_l1_log_hash
public_inputs[3] = data.heap_hash
```

verbatim — **no transformation** (no endianness swap, no padding, no truncation, no field
reduction) between the bytes stored in the output and the bytes passed to the SNARK verifier.
The coords are opaque 32-byte values at the Mintlayer layer; only the proof system interprets
them as field elements.

**Rationale:** any transformation (e.g. `u256` little-endian conversion "for convenience")
creates a coordinate frame mismatch and the false-settlement scenario described in the header.

## 4. Binding rules checked outside the proof (tx-verifier, stateful)

The proof guarantees the coords are internally consistent with the batch execution. The
following is enforced by Mintlayer consensus *in addition*:

| Rule | Where |
|------|-------|
| `batch_number == latest_settled(l2_chain_id) + 1` (strict sequencing) | `connect_transaction` |
| `prev_state_root == state_root settled for batch N-1` **[VERIFY: genesis prev root value for batch 1]** | `connect_transaction` |
| batch not already settled | implied by strict sequencing |
| proof size ≤ `zk_batch_settlement_max_proof_size(height)` | `check_transaction` |
| VK = `zk_vk_for_protocol_version(protocol_version, proof_type)` exactly | `check_transaction` |

## 5. Edge cases the audit must confirm

1. **[VERIFY]** Coord index order (§1 table) — especially: is coord 1 the *previous* root or
   something else (e.g. "exiting pubdata root")?
2. **[VERIFY]** Does the wrapper circuit actually make all four coords *public inputs* of the
   final SNARK, or are some committed inside the proof and only partially exposed? If partially
   exposed, §3 is wrong and must be rewritten.
3. **[VERIFY]** For **Plonk** (protocol < 29): same coord semantics as Fflonk? Same ordering?
4. **[VERIFY]** Batch 1 (`prev_state_root` of the L2 genesis): what canonical value does the
   prover use (zero hash? well-known genesis root?), so Mintlayer can enforce continuity from
   the first batch.
5. **[VERIFY]** `protocol_version` encoding: `ProtocolSemanticVersion` in zkthunder contains
   (minor, patch) semantics — is the `u32` in `ZkBatchSettlementData` the *minor* version?
   Mapping must be injective per VK.
6. **[VERIFY]** CBOR encoding of `L1BatchProofForL1`: is it `ciborium`-produced
   (canonical/deterministic not required), and does the Rust struct round-trip through
   `serde` field names or indices? If field names are used, they are part of this contract.
7. **[VERIFY]** Fflonk proof size bound: confirm ≤ 200 KB covers worst-case Fflonk proof with
   margin at protocol 29, and what the Plonk bound should be.

## 6. Test vectors required for signoff

The audit is not complete without these, generated by the real zkthunder prover:

- V1: valid Fflonk proof for batch N, all four coords correct → **must verify**
- V2: V1 with each of the 4 coords bit-flipped (16 vectors) → **must all reject**
- V3: V1 with two coords transposed (6 permutations) → **must all reject** (ordering canary)
- V4: V1 with `state_root` in the output replaced by an unrelated valid root → **must reject**
- V5: V1 truncated / extended / re-serialized non-canonically → **must reject, never panic**
- V6: proof from protocol ≠ VK protocol → **must reject** (never silently use another VK)
- V7 (optional): same vectors run against the zkSync Solidity verifier via foundry, results
  must match Mintlayer's verifier 1:1.
